# Migration guide for v17
## API keys are no longer preserved in pickled StripeObjects
This change affects integrations that persist StripeObjects in caches or queues and then make requests through the restored objects.

New pickles omit API keys from StripeObjects, including nested objects. Restored objects keep their connected-account routing and API version. Before making object-based requests, pass a key from secure configuration in the method call:
```python
# Before
customer = pickle.loads(trusted_cached_bytes)
customer.refresh()
# After
customer = pickle.loads(trusted_cached_bytes)
customer.refresh(api_key=api_key)
customer.save(api_key=api_key)

customers = pickle.loads(trusted_cached_list_bytes)
for customer in customers.auto_paging_iter(api_key=api_key):
    ...
```
`refresh()`, `refresh_async()`, `save()`, and `auto_paging_iter()` on `ListObject`, `SearchResultObject`, and their V2 equivalents now accept an `api_key` keyword argument for this. Other instance methods, such as `delete()` and resource actions like `cancel()`, already accept request options like `api_key`. Passing a key does not change `stripe.api_key`.

### Global fallback
Plain `pickle.loads()` retains the existing fallback to global API-key configuration. If that is the intended credential, configuring it before making requests is an alternative to passing a key per call:
```python
stripe.api_key = api_key
customer = pickle.loads(trusted_cached_bytes)
customer.refresh()
```
